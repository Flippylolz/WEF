# 20 October 2026 missing recent Telegram offers

Owner-directed, unplanned defect repair requested in Codex chat
`01a15938-2890-7923-b589-62eaca055f73`: new channel listings were missing from
the website for several days. Scope is the existing deterministic address parser,
its regressions, and bounded recovery through the existing current-offer operator.
No dependency, migration, publication-policy or location-review change is needed.

## Diagnosis

At 12:12 UTC, production release `8ad1c5690e2e8590fcd53fa5c5d4f8426934c5d2`
had fresh Telegram transport and aligned source/checkpoint/head `31793`. Recent
delivery reported 24 expected offers, zero missing canonical offers, zero missing
galleries and 19 missing map deliveries. Public facets still ended at
`2026-10-15T14:21:30Z` despite public channel posts on 19 and 20 October.

All 13 canonical offers published after that visible boundary referenced the
same `Unknown location` sentinel. They had `needs_review` visibility. Its latest
selection was an automatic `address_mismatch`; there was no owner selection to
override. The source adapter and media processing were working. The channel's
new multiline location block was unsupported by parser `e2-v18`:

- A location header followed by a separate `ul.` or `Al.` street line.
- A district line followed by an explicitly labeled street line.
- A district label containing both a canonical district and a neighborhood.

A read-only candidate-parser canary over recent unknown-location sources
`31550..31793` identified all 19 with usable source-supported location evidence:
18 street addresses and one district-only location. Only IDs, booleans and
precision categories left the host; no production source text was exported.

The 19 October audit correctly found no missing canonical candidate but did not
identify this shared sentinel as a recoverable address extraction defect.

## Repair and validation

Parser `e2-v19` reads the immediately following street line in a bounded location
block and explicit street labels, retaining exact source spans. Compound district
labels use only recognized canonical comma/pipe segments. Distinct districts or
addresses remain conflicts; another section cannot become a location value.
Street labels remain in source evidence so normalization retains street identity.
Russian abbreviated street prefixes are supported as well. When a post supplies
only an unambiguous canonical district, retain that district as its location;
existing municipal review determines approximate district precision, never a
fabricated street or building point.

Invented fixtures cover the observed forms, CRLF, section boundaries, conflicting
addresses/districts and usable geocode evidence. PostGIS recovery coverage checks
dry-run, application, repeat application, unchanged offer/source identities and
retained review gates. Existing recovery tests protect known locations, owner
selections, hidden offers, deleted revisions and live cursors.

Local validation passed: `make install`, `make lint`, `make format-check`,
`make typecheck`, `make test`, `make contract-check`, and the Markdown link check.
The complete PostGIS/backend suite passed 2,286 tests at 100% line/branch coverage;
355 frontend tests passed with 100% per-file coverage. Temporary wrappers used
the repository's pinned Python, Node and pnpm container runtimes because those
tool versions were not exposed on the host PATH.

The independently gated automatic historical replay keeps its accepted
`e2-v18/source-evidence-v3` baseline and remains disabled. This incident does not
approve or activate a new automatic historical replay generation.

## Production recovery

After green CI and the normal immutable-image release, use
[current-offer backfill](OPERATOR_COMMANDS.md#current-offer-backfill-e28) over a
frozen recent source range. Dry-run first, apply a one-offer canary, verify its
new source-supported location, then apply the reviewed remaining page and repeat
it to confirm stable identities. Allow the existing geocode and publication
loops to validate locations and publish map-ready offers. Never accept the
shared unknown sentinel or bypass address agreement to expose an offer.

Verify public recent-date facets, listings and map responses, photo delivery,
continued live progress and protected unrelated rows. Any unresolved address
remains in the existing place-review workflow. Roll back application images with
the normal release workflow if necessary; no source history or schema is deleted.
