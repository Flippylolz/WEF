# OpenAPI Contract and Frontend Generation

Endpoint behavior is defined in [HTTP API](HTTP_API.md), persisted semantics in the [data model](DATA_MODEL.md), and product behavior in the [product domain](../product/README.md).

## Decision

The canonical API contract is OpenAPI generated by FastAPI.

Planned E19 adds a coarse required `data_origin: "parser" | "ai_assisted"` to
public offer summary/detail schemas. It communicates whether any currently
displayed field has active AI provenance; it is not a quality score. Owner-only
batch, field-origin, source-offset, and parser-gap routes remain outside OpenAPI.

Swagger UI and ReDoc are optional renderers, not the contract. They are not served by the production application. The frontend relies on a committed OpenAPI JSON artifact and generated TypeScript types/client.

Use both distribution forms:

- Commit `contracts/openapi/v1.json` for reviewable diffs, offline frontend work, and reproducible generation.
- Publish the exact schema, generated TypeScript declaration, and static HTML documentation as a GitHub Actions artifact for every successful CI/release commit.

## Repository shape

```text
contracts/
  openapi/
    v1.json
apps/
  backend/
    src/wef/bootstrap/export_openapi.py
  web/
    src/lib/api/
      generated/v1.d.ts
      client.ts
artifacts/                 # ignored; local generated output only
  api-docs-v1.html
```

`contracts/openapi/v1.json` is committed. `v1.d.ts` may be generated during install/build rather than committed; CI must prove generation is deterministic and the frontend compiles against it. Local/static HTML output is not committed unless a later documentation-hosting decision explicitly changes this.

## Backend generation

FastAPI route declarations and Pydantic response/request models are the source definition. A side-effect-free exporter:

1. Constructs the complete application without connecting to PostgreSQL, geocoders, Telegram, or production services.
2. Calls `app.openapi()`.
3. Canonicalizes deterministic JSON ordering/formatting.
4. Writes `contracts/openapi/v1.json` with a final newline.

Conceptual command:

```text
uv run python -m wef.bootstrap.export_openapi --output contracts/openapi/v1.json
```

Schema generation must not require credentials, source data, media, network access, or container startup.

The application composition root must keep route registration separate from runtime resource initialization so importing/exporting the schema has no external side effects.

## Production exposure

Production FastAPI configuration sets:

- `openapi_url=None`
- `docs_url=None`
- `redoc_url=None`

FastAPI still permits offline `app.openapi()` generation while no schema/UI route is registered.

Neither shared Nginx nor the Caddy rollback listener serves the committed contract or static documentation. Production images do not copy `contracts/`, generated HTML, or documentation tooling into runtime stages.

Production smoke/security tests require 404 for common documentation paths, including:

- `/openapi.json`
- `/api/openapi.json`
- `/docs`
- `/redoc`

Local development may enable Swagger UI behind an explicit development-only setting. It is for human exploration only; frontend generation always uses the committed file.

## Schema quality rules

Every public/auth HTTP operation defines:

- Stable explicit `operationId`.
- Tags and concise summary/description.
- Typed path/query/header/body input.
- Explicit success response model and status.
- Shared RFC 9457-style problem responses with stable machine codes.
- Auth/security requirement where applicable.
- Synthetic, non-personal examples where useful.

The generated schema must not contain:

- Production hostnames or environment-specific server URLs.
- Secrets, credentials, internal paths, raw Telegram payloads, or real source/contact data.
- Build timestamps or nondeterministic identifiers.
- Internal CLI/import commands that are not HTTP endpoints.
- Server-rendered Starlette Admin routes/actions under `/admin`; they are owner-console HTML, not frontend API.
- Framework implementation types.

OpenAPI records transport contracts. Business behavior and invariants remain documented in the [product domain](../product/README.md), [data model](DATA_MODEL.md), [HTTP API](HTTP_API.md), and endpoint descriptions rather than duplicated in the frontend.

## Frontend generation

Use:

- `openapi-typescript` as a development/build dependency.
- `openapi-fetch` as the typed runtime HTTP client.

Conceptual generation:

```text
pnpm openapi-typescript contracts/openapi/v1.json --output apps/web/src/lib/api/generated/v1.d.ts
```

Rules:

- The frontend does not handwrite duplicate endpoint/request/response/domain types.
- Generated files are never edited manually.
- `client.ts` configures same-origin base URL, credentials/cookies, request IDs, CSRF header support, and typed error normalization.
- TanStack Query wrappers consume the generated client.
- UI components receive typed presenter DTOs and do not recompute backend rules.
- TypeScript enables strict mode and `noUncheckedIndexedAccess`.

## Static human documentation

Adopt Redocly CLI in development/CI to:

- Lint `contracts/openapi/v1.json`.
- Build a self-contained static HTML reference from the committed schema.

The HTML is:

- Generated into ignored `artifacts/` locally.
- Uploaded to GitHub Actions as `api-contract-{commit_sha}`.
- Never served by Nginx, Caddy, or FastAPI in production.
- Built only from synthetic schema examples.

Swagger UI is therefore unnecessary as a deployed service. Developers may use development-only Swagger UI or open the generated Redocly artifact.

## CI contract pipeline

Run after backend route/schema changes and on every pull request:

1. Generate OpenAPI from the backend into a temporary file.
2. Canonicalize and compare it with committed `contracts/openapi/v1.json`.
3. Fail when the committed contract is stale.
4. Lint the schema with pinned Redocly CLI.
5. Compare the base-branch and proposed schemas with pinned `oasdiff`.
6. Fail on unintended breaking changes to `/api/v1`.
7. Generate `v1.d.ts` from the committed schema.
8. Type-check/build frontend consumers.
9. Build static HTML documentation.
10. Upload JSON, TypeScript declaration, and HTML as one commit-addressed CI artifact.

The CI artifact is evidence for the exact commit. It does not replace the committed schema used by local/frontend development.

## Compatibility policy

- Additive compatible changes remain in `/api/v1`.
- Removal, rename, type narrowing, newly required input, or semantic contract break requires a migration plan and normally a new API version.
- Stable `operationId`, enum values, problem codes, and nullability are compatibility surface.
- A backend change is incomplete until the committed schema, generated client checks, endpoint tests, and affected documentation are updated in the same pull request.
- Emergency exceptions require an explicit owner-reviewed decision; CI drift checks are not silently bypassed.

## Dependency ownership

Backend:

- FastAPI/Pydantic generate the OpenAPI schema.
- The project-owned exporter canonicalizes and writes it.

Frontend:

- `openapi-typescript` generates compile-time types.
- `openapi-fetch` performs typed requests.

Tooling only:

- Redocly CLI lints and renders static HTML.
- `oasdiff` detects breaking OpenAPI changes.

None of the documentation-generation dependencies are installed in production runtime images.

## Acceptance criteria

- A clean checkout can generate frontend types without starting the backend or accessing a network service.
- The committed OpenAPI file is deterministic and matches FastAPI.
- A stale or breaking contract fails CI.
- The frontend compiles only against generated contracts.
- Static HTML is downloadable from CI for humans.
- Production returns 404 for schema/Swagger/ReDoc paths and contains no documentation assets/tooling.
